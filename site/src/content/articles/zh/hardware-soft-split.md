## 结论

一人公司一旦出货实体硬件，必须把**设备固件**、**配套 App** 与可选**云端服务**拆成三条独立发版节奏的产品线。先冻结通信协议并用软件模拟器解耦，让 coding agent 在配套 App 和云端侧全速迭代；固件侧死守板级实测与离线人工签名密钥；至于射频、安规与代工供应链，一律按**本人逐项核实**推进——绝不靠营销话术蒙混过关。

## 第一个交付物：通信契约与四组模拟数据

连接实物前，先写清真实编码方式、消息长度、单位、允许值、协议版本、超时时间和错误响应。下方模板只是草图，不是可直接发送的线协议，也不是有效厂商标识。

| 模拟情况 | 配套应用应有的行为 |
|---|---|
| 有效状态帧 | 显示约定状态与正确单位 |
| 不支持的协议版本 | 提示版本不兼容，不自行猜测 |
| 格式错误或越界值 | 拒绝输入，保留上一个有效状态 |
| 设备断开或超时 | 给出重连提示，不谎报成功 |

**通过标准：** 确定性模拟器能产生四种情况，界面逐一正确响应。再在实物上关闭 Wi-Fi/蜂窝但保留 BLE 或 USB，重测关键情况，记录设备型号、固件版本、应用版本和结果。模拟器通过不等于射频、电源安全、OTA 恢复或法律合规通过，这些需要独立台架证据和目标市场核验。

> [!FLOW] 软硬解耦的四段式交付管线
>
> 1. **冻结通信契约** — 先定义 BLE/USB 数据帧并写出纯软件 Mock 设备模拟器。
> 2. **Agent 构建配套 App MVP** — 对着模拟器快速打磨配对交互、离线控制与自动化测试。
> 3. **板级在环固件验证** — 在真实开发板与样机上验证 Bootloader、看门狗与射频功耗。
> 4. **离线人工签名与合规核验** — 离线私钥签名 OTA 固件，核实目标市场法规授权后再接付费订单。

| 层级 | 核心职责 | 发版节奏 | Coding Agent 适配度 | 混为一谈的高危后果 |
|---|---|---|---|---|
| **1. 设备固件** | Bootloader、外设驱动、射频协议栈、电池保护、OTA 验签 | 低频、严控门禁、真机实测 | **中** — 适合写协议解析与单测；脱离真机闭环极易翻车 | 用户设备变砖、续航崩盘或未签名固件被刷入 |
| **2. 配套 App** | BLE/USB 发现配对、本地参数配置、诊断日志、固件包传输 | 高频（按周迭代商店包或 Web 端） | **高** — 只要有确定性 Mock 设备即可闭环自测 | 拔掉测试板就跑不了测试，或断网即无法配对 |
| **3. 云端（可选）** | 可选账号备份、多端同步、经用户同意的崩溃遥测 | 持续独立部署 | **高** — 标准 Web/API 切片（见[先写规格](/zh/articles/spec-first-agent-loop/)） | 周末云服务抖动或日后停服，连带把实体硬件彻底废掉 |

## 前置条件

- 明确界定硬件品类与目标销售司法辖区（例如纯有线 USB-C HID 配件 vs 面向北美/欧盟销售的蓝牙无线发射设备）
- 已收集目标市场的一手监管入口与安全基线文档（如 FCC 设备授权指南与 CISA Secure by Design 准则）
- 软件仓库具备自动化验证命令，并通过规则文件划清 agent 可改目录与禁区（[规则文件 + hooks](/zh/articles/rules-hooks/)）

## 执行步骤

1. **画板和建仓前先写软硬边界一页纸：** 明确哪些逻辑留在固件、哪些放进配套 App，并立下硬规矩——**完全断网时核心硬件功能必须照常可用**。
2. **先定带版本号的通信契约 + 软件模拟器：** 把 BLE 特征值或串口/USB 指令帧写成清晰结构，让 coding agent 不插实物也能测试已定义的应用状态；覆盖程度以你自己的测试用例为准。
3. **用人工离线密钥锁死固件升级入口：** 在任何外部内测开始前就写好 Bootloader 签名校验，生产私钥全程离线保管，严禁放进仓库或 agent 环境（[安全速查](/zh/articles/security-quickcheck/)）。
4. **逐项跑通下方「自行核实清单」：** 只有你亲手拿到原厂规格书、模组授权边界条件或实验室报告原件时才打勾。
5. **用已核实证据反审落地页文案：** 严格区分「采用已过认证的射频模组」（整机往往仍受天线、外壳与主控集成规则约束）与「整机已完成目标市场认证」。

## 营销声明 vs 合规事实对照

| 容易踩坑的宣传话术 | 工程与监管现实 | 稳妥诚实的 OPC 做法 |
|---|---|---|
| *「已获 FCC / CE 认证」*（直接照抄内部蓝牙模组宣传图） | 模组授权仅在特定天线、屏蔽与宿主集成条件下有效；装进你的外壳后往往仍需核验整机辐射/集成合规 | 仅在核对一手法规条款或取得合格实验室文件后，如实表述具体合规状态 |
| *「全自动云端静默升级固件」* | 一旦 CI 误推未签名或坏包，几分钟内就能让所有已售硬件集体变砖 | 设备端强制公钥验签、离线人工签名发版，并保留按键进入恢复模式（DFU）的救砖路径 |
| *「先注册登录云账号才能配对开机」* | 把一个买断制实体小硬件的寿命永远绑死在你个人的后端服务器上 | 本地 USB/BLE 免登录直连优先；云同步只做锦上添花的可选项 |

> [!WARNING] 仅供工程定向——不构成法律或检测机构意见
> 本站不销售硬件合规服务，也不提供任何认证背书。无线电发射、锂电池航空/陆路运输、产品安规与进出口标签均涉及明确法律责任——正式销售受监管硬件前，请务必查阅目标市场官方监管指南并咨询具备资质的检测实验室或专业顾问。

## 可直接复制的软硬边界与模拟通信模板（`specs/hardware-split.md`）

把清晰的软件契约交给 coding agent，同时把签名密钥与合规表述挡在门外：

```markdown
# 软硬边界与通信契约：[设备名称]

- **产品类别与目标市场：** [例如：BLE 桌面计时器 — 北美市场]
- **离线优先硬规则：** 关闭 Wi-Fi 和蜂窝数据，保持 BLE 或 USB 可用，验证已定义的本地配对与核心控制。
- **OTA 签名权限：** Bootloader 使用设备支持的算法与信任链验证签名；记录密钥负责人和离线签名流程。

## 通信协议契约 v1（固件与 App 模拟器共用）
- **物理传输层：** [BLE GATT / WebUSB / 串口]
- **传输标识：** [BLE 填真实服务与特征 UUID；USB 填已分配 VID/PID；串口填端口与帧配置。这些标识不能互换。]
- **状态上报帧（设备 → App）：** `{ protocolVersion: 1, batteryMv: number, mode: "idle" | "active", fwVersion: string }`
- **控制指令帧（App → 设备）：** `{ cmd: "set_mode" | "ping", payload: ... }`

## Agent 工作区权限边界
- **允许自主编码与自测：** `companion-app/`、`mock-device/`、`protocol/tests/`
- **必须真机板级在环复核：** `firmware/drivers/`、`firmware/bootloader/`
- **Agent 绝对禁区：** 离线 OTA 签名私钥、认证合规宣传文案、工厂 BOM 关键料号替换
```

## 自行核实清单（非法律意见）

- [ ] 核心元器件与无线模组供应商已明确，原厂规格书（Datasheet）已在本地归档留存
- [ ] 已结合**你自己的**外壳材质、PCB 走线/天线方案与共址情况，核对射频模组授权条件（适用时通过官方 FCC ID 等渠道核查）
- [ ] 已核查目标市场的电源保护、温升及锂电池充放电/运输安全要求
- [ ] 机身铭牌、包装标签与说明书声明同实测行为及真实合规进度完全一致
- [ ] 生产环境 OTA 签名私钥已在离线环境生成并冷备份；coding agent 从未接触任何密钥材料
- [ ] 开启任何诊断或崩溃遥测采集**之前**，配套 App 隐私政策已如实披露数据范围
- [ ] 代工厂 / 贴片厂（CM）的保密协议（NDA）、锁料清单与工程变更通知（ECN）对接人已建档
- [ ] 开放付费下单前，已备妥首单损坏（DOA）换货、本地救砖模式说明与售后退换（RMA）通道

## 完成定义

- [ ] 公开营销页与商店详情绝不出现任何未经本人核实的认证徽章、安规承诺或虚标续航/距离参数
- [ ] 配套 App 可在无生产云依赖的情况下，对着确定性软件模拟器跑通端到端冒烟测试
- [ ] 固件构建具备明确版本号与可复现产物，且任何对外升级包均须经人类离线签名放行

## 反模式

- **把生产固件签名私钥放进 `.env` 或 agent 可读取的 CI 变量里** — 一次令牌泄露或提示注入就等于把全量用户设备的刷机权拱手让人。
- **因为采购的蓝牙芯片印过认证标志，就在整机落地页直接贴满「FCC / CE 认证」徽章** — 极易招致海关扣货、平台下架或监管处罚。
- **v1 连改个本地按键配置都强制走一趟云端登录往返** — 服务器一旦半夜重启，硬件口碑当场崩塌。
- **让 coding agent 在没有真机在环测试的情况下重构底层电源管理或 Flash 擦写代码** — 编译零警告的 C/Rust 代码照样可能把电池过放或把启动区擦坏。
